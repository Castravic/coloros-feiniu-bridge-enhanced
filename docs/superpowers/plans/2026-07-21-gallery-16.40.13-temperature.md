# 相册 16.40.13 温控兼容与迟滞修复计划

## 目标

用户选择修复最终审查发现的温控迟滞缺陷：高温暂停后的前后台切换不能解除暂停。保持前台 45°C、后台 43°C、恢复 41°C 不变，并继续适配 16.40.13 的 `u0q` 与 `r570`。

## 实现边界

- `CloudBackupTemperaturePolicy.blocked` 在温度超过当前模式上限后设为 `true`，且仅当实际温度 `<= CLOUD_RETRY_TEMPERATURE_C` 时复位。
- 删除 `lastForeground` 及前后台切换复位；前后台切换仍会重新选择 45°C 或 43°C 上限，但不清除既有高温暂停状态。
- 保持备份条件线程局部作用域、温度映射、日志、非温度暂停条件和 `getGalleryStat` 回退不变。
- 保留 `bsf`、`f0q`、`u0q` 与 `vwp`、`l370`、`r570` 的候选兼容。

## 契约测试与夹具

`scripts/verify-gallery-temperature-compat.ps1` 默认读取已提交的最小夹具：

- `scripts/fixtures/gallery-16.40.13/com/oplus/aiunit/vision/u0q.java`
- `scripts/fixtures/gallery-16.40.13/com/oplus/aiunit/vision/r570.java`

测试要求 `r570.a()` 位于 `u0q.a(boolean, boolean): PauseReason` 方法体内；`u0q` 与 `r570` 分别位于对应 Kotlin 候选数组块。参数名和温度局部变量使用任意合法 Java 标识符，不绑定 JADX 的 `z`、`z2` 或 `fA`。测试还禁止生产 Hook 出现 `lastForeground`，并要求唯一的 `blocked = false` 位于 `actualTemperature <= CLOUD_RETRY_TEMPERATURE_C` 分支。

完成默认夹具验证后，使用显式 `-CurrentSources .analysis/jadx-classes2/sources` 对真实反编译源码运行同一套契约。

## 验收步骤

1. 先只加入夹具与收紧的契约测试，在旧 Hook 上观察 RED：`lastForeground` 仍会导致错误复位。
2. 删除生产 Hook 的 `lastForeground` 与切换复位，再观察默认夹具及真实 JADX 源码均 GREEN。
3. 回归运行 `verify-gallery-stat-fallback.ps1`、`verify-token-decryption-diagnostics.ps1` 和计划中的旧版/16.40.8/当前 DEX `verify-gallery-compat.ps1`。
4. 使用 JDK 17、Android SDK 35、Gradle 8.7 运行 `:app:compileDebugKotlin --no-daemon`，随后运行 `clean :app:assembleDebug --no-daemon`。
5. 复制调试 APK 为 `coloros-feiniu-bridge-16.40.13-temperature-debug.apk`，验证 v2 签名和 SHA-256；枚举并检查全部 `classes*.dex`，确认 `u0q`、`r570` 及 `backup temperature compatibility installed` 标记。

## 不在范围内

- 提高或改变 45/43/41°C 阈值。
- 改变非温度暂停条件、线程局部范围或 `getGalleryStat` 回退。
- 声称未做运行时修复；本次明确修改了迟滞状态复位行为。
