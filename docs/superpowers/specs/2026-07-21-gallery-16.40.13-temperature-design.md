# Gallery 16.40.13 Backup Temperature Compatibility Design

## Goal

Restore the module's existing bounded backup-temperature policy on ColorOS Gallery 16.40.13 without disabling thermal safety or affecting Gallery scanning, OCR, editing, and other non-backup temperature checks.

## Confirmed root cause

Gallery 16.40.13 retains the same Feiniu backup temperature algorithm but changes the obfuscated classes:

- Feiniu backup condition checker: `f0q` becomes `u0q`.
- Gallery temperature utility: `l370` becomes `r570`.

`u0q.a(boolean, boolean)` calls `r570.a()` and applies the original hysteresis: allow at or below 37°C, block above 38°C, and preserve the previous state between those values. The current module only lists the older class candidates, so its logs report `backup temperature compatibility unavailable` and the original 37/38°C policy remains active.

## Selected approach

Extend the existing verified candidate lists rather than introducing dynamic DEX scanning or replacing `HIGH_TEMPERATURE` results:

1. Add `com.oplus.aiunit.vision.u0q` to `BACKUP_CONDITION_CHECKER_CLASSES`.
2. Add `com.oplus.aiunit.vision.r570` to `TEMPERATURE_UTIL_CLASSES`.
3. Continue verifying the existing method shapes before installing hooks:
   - `u0q.a(boolean, boolean): PauseReason` for the raw backup-condition scope.
   - `u0q.b(boolean, boolean): PauseReason` for pause-state diagnostics.
   - `r570.a(): float` for the raw temperature reading.
4. Reuse `BackupConditionEvaluationScopeHook`, `RelaxBackupTemperatureHook`, and `CloudBackupTemperaturePolicy` unchanged.

This keeps the Hook restricted to temperature reads made while the Feiniu backup condition checker is executing. Calls from OCR, face scanning, geographic analysis, editing, and other Gallery components remain untouched.

## Temperature policy

Keep the current module thresholds exactly:

- Foreground backup: allow up to 45°C; block above 45°C.
- Background backup: allow up to 43°C; block above 43°C.
- After a thermal block, resume only at 41°C or below.
- When the module allows a reading above Gallery's original 37°C threshold, report 37°C only to the current Feiniu backup-condition evaluation so Gallery continues checking network, battery, power-saving mode, official cloud synchronization, and other pause reasons.

The module does not force backup above its own limit and does not bypass any non-temperature condition.

## Diagnostics and privacy

Existing bounded logs remain sufficient:

```text
backup pause diagnostics installed
backup temperature compatibility installed foregroundMax=45.0C backgroundMax=43.0C retry=41.0C
backup temperature policy actual=N.C foreground=true|false max=N.C retry=41.0C allow=true|false
backup pause state=HIGH_TEMPERATURE|NONE|OTHER_REASON
```

No token, device identifier, NAS address, album/photo metadata, or filename is added to temperature diagnostics.

## Testing

Static compatibility verification will first fail because `u0q` and `r570` are absent from the Hook source, then pass after both candidates are added. Existing tests for `f0q`, `l370`, `op80`, token diagnostics, and Gallery-stat fallback must remain green.

The Android debug build must succeed with JDK 17, Android SDK 35, build-tools 35.0.0, and Gradle 8.7. The final test APK must pass APK v2 signature verification and contain the `u0q`, `r570`, and temperature-policy markers.

Device validation succeeds only when LSPosed logs show both compatibility hooks installed and, at a temperature between the original and module limits, `backup temperature policy ... allow=true`. The backup must then either run or expose a different genuine pause reason; an installation log by itself is not success.

## Out of scope

- Investigating why rooted sessions fail `getGalleryStat`.
- Changing the already-working real-album fallback.
- Removing or raising the existing 45/43/41°C safety limits.
- Adapting unrelated 16.40.13 pause-reason text or mobile-data classes unless they are required for temperature validation.
