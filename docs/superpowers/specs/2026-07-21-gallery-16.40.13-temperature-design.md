# 相册 16.40.13 备份温控兼容设计

## 目标

在 ColorOS 相册 16.40.13 上恢复模块有限度备份温控策略，并修复用户选择处理的迟滞缺陷：前后台切换不得解除高温暂停。温度安全保护和相册扫描、文字识别、编辑等与备份无关的温度检查保持不变。

## 已确认的根因

相册 16.40.13 保留了原有的飞牛备份温控算法，但再次修改了混淆类名：

- 飞牛备份条件检查器：由 `f0q` 变为 `u0q`。
- 相册温度工具类：由 `l370` 变为 `r570`。

`u0q.a(boolean, boolean)` 会调用 `r570.a()` 获取温度，并执行原厂迟滞判断：温度不高于 37°C 时允许备份，高于 38°C 时暂停，在 37°C 至 38°C 之间保持先前状态。当前模块只包含旧版候选类，因此日志显示 `backup temperature compatibility unavailable`，相册继续使用原厂 37/38°C 温控策略。

## 选定方案

扩充已经验证过的候选类列表，并修正温控状态复位，不引入动态 DEX 扫描，也不直接改写 `HIGH_TEMPERATURE` 返回结果：

1. 将 `com.oplus.aiunit.vision.u0q` 加入 `BACKUP_CONDITION_CHECKER_CLASSES`。
2. 将 `com.oplus.aiunit.vision.r570` 加入 `TEMPERATURE_UTIL_CLASSES`。
3. 安装 Hook 前继续校验现有方法形状：
   - `u0q.a(boolean, boolean): PauseReason`：飞牛备份原始条件检查范围。
   - `u0q.b(boolean, boolean): PauseReason`：备份暂停状态诊断。
   - `r570.a(): float`：原始温度读数。
4. 原样复用 `BackupConditionEvaluationScopeHook`、`RelaxBackupTemperatureHook`，并在 `CloudBackupTemperaturePolicy` 删除 `lastForeground` 与前后台切换时的 `blocked = false`。

高温阻断一经设定，只会在实际温度 `<= 41°C` 时复位；切换到前台或后台仅改变本次判断的 45°C/43°C 上限。这样可以确保 Hook 只调整飞牛备份条件检查期间读取的温度。文字识别、人脸扫描、地理分析、编辑及相册其他组件的温度读取均保持原样。

## 温控策略

严格保持模块现有阈值：

- 前台备份：不高于 45°C 时允许，高于 45°C 时暂停。
- 后台备份：不高于 43°C 时允许，高于 43°C 时暂停。
- 因温度暂停后，仅在温度降至 41°C 或以下时恢复。
- 当模块允许一个高于相册原厂 37°C 阈值的温度时，只在当前飞牛备份条件检查中将读数调整为 37°C，使相册能够继续检查网络、电量、省电模式、官方云同步及其他暂停原因。

模块不会在超过自身温度上限时强制备份，也不会绕过任何非温度条件。

## 诊断与隐私

继续使用现有的有限次数日志：

```text
backup pause diagnostics installed
backup temperature compatibility installed foregroundMax=45.0C backgroundMax=43.0C retry=41.0C
backup temperature policy actual=N.C foreground=true|false max=N.C retry=41.0C allow=true|false
backup pause state=HIGH_TEMPERATURE|NONE|OTHER_REASON
```

温控诊断不会增加 token、设备标识、NAS 地址、相册或照片元数据、文件名等敏感信息。

## 测试方案

先加入默认最小夹具和收紧后的静态兼容验证，使其在旧 Hook 上因 `lastForeground`/状态切换复位而失败；删除该状态和复位后测试应通过。测试必须验证 `r570.a()` 位于 `u0q.a(boolean, boolean): PauseReason` 方法体内，且 `u0q`、`r570` 分别位于对应候选数组块；参数名和温度局部变量不绑定 JADX 名称。默认夹具位于 `scripts/fixtures/gallery-16.40.13`，还必须以显式 `.analysis/jadx-classes2/sources` 运行同一契约。现有针对 `f0q`、`l370`、`op80`、token 诊断和相册统计回退的测试必须继续通过。

Android 调试构建必须使用 JDK 17、Android SDK 35、build-tools 35.0.0 和 Gradle 8.7 并成功完成。最终测试 APK 必须通过 APK v2 签名验证，并在全部 `classes*.dex` 中检索到 `u0q`、`r570` 和温控策略标记。

设备验证只有在 LSPosed 日志同时显示两个兼容 Hook 已安装，并在温度介于原厂阈值和模块阈值之间时出现 `backup temperature policy ... allow=true`，才算成功。随后备份应开始运行，或者展示另一个真实暂停原因；仅有 Hook 安装日志不算成功。

## 不在本次范围内

- 调查 Root 环境下 `getGalleryStat` 失败的原因。
- 修改当前已经正常工作的真实相册列表回退。
- 移除或提高现有 45/43/41°C 安全阈值。
- 适配与温控验证无关的其他 16.40.13 暂停原因文案或移动数据类。
