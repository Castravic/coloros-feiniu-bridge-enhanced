# v0.4.3 release validation

Date: 2026-10-28 (Asia/Shanghai). Version `0.4.3`, versionCode `18`.

## Behavior

Images created while Gallery was closed could remain absent on the first open,
then appear after a background/foreground transition. The repair observes the
native local-sync listener and replays its startup callback once if registration
finishes after Gallery is already in the foreground and no native start was seen.
It preserves the Gallery callback's own permission checks, sync policy and queue.

Only inspected Gallery 16.50.8 and 17.10.7 mappings are eligible. Unknown versions
skip this repair rather than guessing obfuscated classes. The user confirmed that
the trial APK fixed the reported reproduction. This does not establish that every
Gallery backup/network feature has passed device testing.

## Review

- Promoted the device-confirmed repair from the Debug trial to both build types.
- Preserved once-per-listener replay, native-start suppression, main-thread posting,
  weak references and exact Gallery version/method guards.
- Only a successfully completed registration coroutine can trigger compensation.
- Kept bulk refresh diagnostics off by default in Debug and always off in Release;
  `-PrefreshDiagnostics=true` enables the bounded Debug capture when needed.
- Reviewed prefix fallback caching and lazy DEX method-signature decoding, retaining
  their regression coverage and original exception/installation behavior.

## Validation

- Debug and Release each ran 120 tests: 117 passed, 3 unrelated optional inputs
  skipped, zero failures/errors. Both real 16.50.8 and 17.10.7 validations ran,
  including the new local-startup coroutine/callback contracts.
- Debug/Release builds and release vital lint passed.
- Four PowerShell source checks and both local JADX contract scripts passed.
- Release BuildConfig is `0.4.3` / `18` with diagnostics disabled; compiled Release
  recovery code retains its installation path rather than a Debug-only early return.
- CI runs both test variants and publishes both reports; proprietary inputs are
  intentionally unavailable there.

Signed final APK verification and its digest are recorded in the release notes.
